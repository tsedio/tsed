## ADDED Requirements

### Requirement: Ts.ED routes execute through a Fetch handler

The v9 HTTP core SHALL expose a public factory that creates a handler accepting a standard `Request` and resolving to a standard `Response` for a Ts.ED route already selected and compiled by a host bridge.

#### Scenario: Execute a decorated route without a server

- **WHEN** a caller sends a `Request` to the handler for a compiled controller route
- **THEN** the handler SHALL resolve to the response generated by that route without requiring an Express, Fastify, Koa, or Node server instance

#### Scenario: Leave unmatched requests to the host router

- **WHEN** a request does not match a host-registered route
- **THEN** the host router SHALL produce its configured not-found response and the Fetch execution handler SHALL NOT implement route matching

### Requirement: Fetch handler preserves the Ts.ED execution pipeline

The Fetch handler SHALL execute route parameter binding, DI scopes, middleware, exception handling, response filtering, and request/response lifecycle hooks through the shared HTTP core.

#### Scenario: Convert a thrown controller error

- **WHEN** a decorated controller throws while processing a Fetch request
- **THEN** the handler SHALL use the configured Ts.ED exception pipeline to produce the final `Response`

#### Scenario: Finalize a filtered controller result

- **WHEN** a controller returns a value handled by a Ts.ED response filter
- **THEN** the handler SHALL return a `Response` containing the filtered representation and configured status and headers
